Field

[0003] The present disclosure relates to application-specific integrated circuits (ASICs). More particularly, it relates to a revenue processor node that performs transaction ingestion, telemetry ingestion, cryptographic processing, and network-isolation enforcement in dedicated silicon deployed at network edge locations and within core transaction datacenters.

Background

[0004] Transaction, metering, and logistics workloads are commonly implemented as software microservices executing on general-purpose processors. Each transaction typically traverses an operating system network stack, shared memory, and one or more networked databases before it is recorded. This arrangement introduces latency that varies with load, and it places application logic, key handling, and network access within a single shared trust domain.

[0005] Three problems follow from this arrangement. First, high-volume retail traffic can saturate the same processing pipelines that carry high-value bulk enterprise trade, so a spike in one class of traffic can delay the other. Second, cryptographic operations performed in software share memory and privilege boundaries with application code, which weakens the isolation of key material. Third, industrial and logistics systems connected to external networks can receive remote commands that alter physical processes, and isolation implemented only in software can be bypassed or disabled by an attacker who has compromised the host.

[0006] Transit infrastructure such as ports, rail corridors, and highways also produces high-velocity telemetry. Recording that telemetry as append-only time-series entries requires buffering that absorbs bursts without stalling the processes that compute tariffs from it.

[0007] There is a need for a processing node in which ingestion, computation, cryptography, and network isolation are separated in hardware, so that each function has a dedicated datapath and a defined trust boundary.

Summary

[0008] In one aspect, a revenue processor node is provided. The node includes an ingestion domain with separate transceiver interfaces for a first commerce track and a second commerce track, the two tracks being arbitrated so that traffic on one does not block traffic on the other. A supplier bidding interface, coupled to a low-latency cache, computes assignment parameters as checkout events arrive. An order queuing buffer packages orders into standardized message payloads.

[0009] The node further includes a toll processing domain with inputs for telemetry, hardware arithmetic units that compute tariffs, and a time-series buffer that accepts append-only entries. A cryptographic domain, physically separated from the ingestion and toll processing domains, includes encryption and hash accelerators, a tamper-resistant key store, and mutual TLS hardware. An isolation gate includes a write-lock that prevents modification of active control programs without a verification signal, a self-quarantine trigger, and a blast-radius circuit that asserts a link-drop signal when a threat indicator or a malformed-frame count exceeds a threshold. A revenue pooling bus receives processed values and appends them to a ledger.

[0010] In another aspect, a method of responding to an internal anomaly in a revenue processor node, and a method of processing transactions at an edge node, are provided, as set out in the claims.

Detailed Description

Overview

[0013] Reference is made to FIG. 1. A revenue processor node 100 is implemented as a single integrated circuit in an example embodiment fabricated in a 5 nanometer FinFET process. The node is deployed at each of a plurality of coastal hubs, for example on the order of 2,147 hubs in one example deployment, and within core transaction datacenters. The node 100 may operate as a standalone processor or as one of several nodes coupled by a ring bus 109.

[0014] The node 100 comprises an ingestion and commerce engine 102, a toll processing domain 110, a cryptographic domain 118, an isolation gate 126, and a revenue pooling bus 134. Data passes from ingestion to toll processing, and from toll processing to the revenue pooling bus, only through the cryptographic domain. Control signals from the isolation gate reach the other domains without passing through software.

[0015] As used herein, the gatekeeper refers to the isolation gate 126 together with the write-lock 128, the self-quarantine trigger 130, and the blast-radius circuit 132. The gatekeeper is the only path by which an external command can reach connected automation equipment, and it is implemented in hardware that software executing on the node cannot reconfigure.

Ingestion and Commerce Engine 102

[0016] The ingestion and commerce engine 102 is the entry point for interactions with buyers and enterprise counterparties. It includes a commerce interface 104, a supplier bidding interface 106, and an order queuing buffer 108.

[0017] The commerce interface 104 includes transceiver pins and associated serializer-deserializer lanes that are separated by track. A first track carries bulk enterprise trade (Track A), and a second track carries global retail marketplace traffic (Track B). Each track has its own input queue and arbiter. The arbiters are independent, so that a surge in Track B traffic cannot back-pressure Track A. In one example, Track B is provisioned to serve a retail population of up to several billion buyer accounts in aggregate across the deployment, for example 6.0 billion. The separation is maintained in silicon, not by a software scheduler.

[0018] The supplier bidding interface 106 is a dedicated block coupled to an ultra-low-latency cache 107. When a checkout event clears on Track B, the block computes factory assignment parameters from bid state held in the cache and returns them without invoking a processor core. Because the cache is local to the block, the computation does not wait on external memory.

[0019] The order queuing buffer 108 is an SRAM-backed buffer. It receives raw orders, packages each order into a standardized message payload, and stream-loads the payloads onto the ring bus 109. The buffer decouples the arrival rate of orders from the rate at which downstream domains accept work.

Toll Processing Domain 110

[0020] The toll processing domain 110 computes transactional tariffs from transit telemetry. It includes telemetry inputs 112, a toll calculation engine 114, and a time-series buffer 116.

[0021] The telemetry inputs 112 are input pipelines that continuously receive data from deepwater ports, electrified rail corridors, and smart highways. Each pipeline is protocol-specific and terminates in a common message format.

[0022] The toll calculation engine 114 includes hardware multiply-accumulate arrays and comparator units that compute tariffs from telemetry quantities. In one example, the engine computes a truck tariff of 0.15 per kilometer and a rail tariff of 0.02 per ton-kilometer. The tariff parameters are held in configuration registers within the engine. The registers can be written only through an authenticated configuration update that is verified by the cryptographic domain 118 before it takes effect.

[0023] The time-series buffer 116 temporarily stores high-velocity transit telemetry and permits sequential, append-only entries to stream into database arrays. Writes to the buffer are not blocked by reads or by the toll calculation engine, so that database persistence does not stall tariff computation.

Cryptographic Domain 118

[0024] The cryptographic domain 118 is a security domain that is physically and logically isolated from the ingestion and toll processing domains. It has its own power gating and clock tree. Its only path to the other domains is a one-way gateway first-in, first-out buffer. Data entering the cryptographic domain from the other domains is not returned to them except as processed output.

[0025] The cryptographic domain includes an AES-256 encryption accelerator and a SHA-512 hash accelerator, shown together as block 120. Every inbound and outbound ledger entry is encrypted or hashed in block 120 before it leaves the die, so that transaction data is protected at the chip boundary.

[0026] The key management vault 122 is a tamper-resistant silicon storage region that holds the root cryptographic keys of the node. The vault includes tamper sensors. When a sensor reports a physical intrusion, the vault zeroizes its contents before any key can be read out.

[0027] The mutual TLS block 124 is a hardware networking block that performs handshake, certificate verification, and record protection for connections between regional edge nodes. Performing these steps in hardware mitigates man-in-the-middle attacks at the transport layer without relying on a software network stack.

DRM and Isolation Gate 126

[0028] The isolation gate 126 enforces a security level parameter, referred to in one embodiment as Security Level 4, across the factory equipment connected to the node. The gate includes a write-lock 128, a self-quarantine trigger 130, and a blast-radius isolation circuit 132.

[0029] The write-lock 128 is a hardware barrier between the external interface and the programming memory of connected automation equipment. A command that would alter an active robotic assembly program is passed only when a verification signal is present. The verification signal may be generated by a physical actuator or by an authenticated out-of-band input. The write-lock cannot be reconfigured by software running on the node.

[0030] The self-quarantine trigger 130 is an automated circuit loop linked to stress-test matrices within the node. When a stress test fails, or when an internal consistency check indicates that a memory region has been altered, the trigger places the node in a quarantine state in which external writes are refused and only local, verified operations proceed.

[0031] The blast-radius isolation circuit 132 monitors a count of malformed data frames received from the external network and a threat indicator produced by the cryptographic domain 118 or by the node's intrusion logic. If the threat indicator is asserted, or if the count exceeds a threshold, the circuit asserts a link-drop signal. The link-drop signal disconnects the external network interface. In one example, the threshold is 5,000,000 malformed frames per hour. The circuit keeps the local, air-gapped automation within the facility under control, so that grid stability and local production continue after the external link is removed.

Gatekeeper and Internal Anomaly Self-Quarantine

[0032] The isolation gate 126 includes a quarantine controller that holds one of four states: NORMAL, QUARANTINE, LINK-DROP, and ZEROIZED. In the NORMAL state, external writes are passed to the write-lock 128 subject to the verification described above. In the QUARANTINE state, external writes are refused and only local, verified operations proceed. In the LINK-DROP state, the external network interface is disconnected. In the ZEROIZED state, key material in the key management vault 122 has been erased.

[0033] Two classes of event drive the quarantine controller. An internal error originates within the node. Examples include a failure of a stress-test circuit in the self-quarantine trigger 130, a parity or consistency fault in a memory region of the ingestion domain 102 or the toll processing domain 110, a mismatch between redundant computations, an out-of-range tariff result from the toll calculation engine 114, and a sequence error in the time-series buffer 116. An external anomaly originates from the external network, for example a malformed-frame count or a threat indicator as described in paragraph [0031].

[0034] Internal errors are routed to the QUARANTINE state, and external anomalies are routed to the LINK-DROP state. The routing is determined by the origin of the event, not by its magnitude alone. Quarantining the write path leaves local automation and the ledger in place, so that the node can continue local operation while the external path is refused or cut off.

[0035] A severity aggregator in the isolation gate 126 combines error signals from the ingestion domain 102, the toll processing domain 110, and the cryptographic domain 118. Because the cryptographic domain is coupled to the other domains only through the one-way gateway, the aggregator receives status from those domains but returns no signal to them except the quarantine and link-drop controls it issues.

[0036] The severity aggregator applies a response ladder. A single correctable event is logged. Repeated events within a monitoring window escalate to QUARANTINE. A quarantine combined with a threat indicator escalates to LINK-DROP. A tamper event from the key management vault 122 escalates to ZEROIZED from any other state. Each transition is written as an entry of the append-only ledger before the new state takes effect.

[0037] Exit from QUARANTINE requires a recovery verification. The verification is a physically actuated or out-of-band authenticated signal, and software executing on the node cannot generate it. The controller records the reason for quarantine in one-time-programmable memory, so the quarantine state persists across power cycles. Exit from LINK-DROP requires the same verification and a reset of the malformed-frame counter. ZEROIZED is not exited in the field and requires a factory-controlled provisioning process.

[0038] Because the write-path gate is driven by the state register and not by processor software, external write transactions are refused during quarantine, while the ingestion domain 102 and the toll processing domain 110 continue to process local transactions and the connected automation continues to operate under local control. A software fault that corrupts the processor cannot clear the quarantine encoding, and the reason code survives power cycling.

Revenue Pooling Bus 134

[0039] The revenue pooling bus 134 receives processed transaction values from the ingestion and toll processing domains and provides them to a ledger. It includes an aggregator 136, a ledger block 138, and a disbursement controller 140.

[0040] The aggregator 136 evaluates incoming transaction values and applies a configured allocation ratio to values associated with designated manufacturing value-added transactions. In one example, the allocation ratio is 60/40. The ratio is a configuration parameter and is not fixed in silicon.

[0041] The ledger block 138 extracts a configured transaction tax, for example 2 percent of the processed value, and appends metadata for each transaction to an append-only ledger structure. Each appended entry is encrypted by block 120 before storage.

[0042] The disbursement controller 140 routes amounts from the pool according to a configured schedule. In one example, outputs remain disabled until a ledger status signal indicates that the pool is free of encumbrances.

Alternative Embodiments

[0043] The functions described above may be distributed across multiple chiplets in a single package, with each chiplet implementing one domain and the domains communicating through a die-to-die interface that preserves the one-way gateway between the cryptographic domain and the other domains. The node may also be prototyped on a field-programmable gate array, with the understanding that the isolation properties described herein require the domains to be physically separate in the production device. Thresholds, tariff parameters, allocation ratios, and tax rates are described as configuration values, and other values may be used.

[0044] Terms such as "approximately" and "about" refer to values within ten percent of the stated value unless otherwise indicated.

Abstract

A revenue processor node implemented in dedicated silicon separates transaction ingestion, telemetry processing, cryptographic operations, and network isolation into hardware domains. Independently arbitrated transceiver interfaces keep a retail commerce track from blocking a bulk enterprise track. Hardware arithmetic units compute tariffs from transit telemetry and store the results in an append-only buffer. A cryptographic domain, reached only through a one-way gateway, encrypts and hashes ledger entries and holds keys in a tamper-resistant store. A gatekeeper isolation gate quarantines the external write path in response to internal errors, disconnects the external network link in response to external anomalies, and requires a verification signal that software cannot generate to exit quarantine.
